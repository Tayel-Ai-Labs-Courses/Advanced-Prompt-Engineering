## 4. المفهوم الأول: النوايا (Intents)

**النية = العميل عايز إيه؟**

الكلام ممكن يتقال بألف طريقة، بس النية محدودة. "عايز بيتزا"، "ممكن أطلب"،
"هاخد مارجريتا" — كلهم نية واحدة اسمها `order_pizza`.

في `nlp.py` عندنا 10 نوايا:

| النية | يعني إيه | مثال |
|---|---|---|
| `greet` | بيسلّم | السلام عليكم |
| `check_menu` | عايز المنيو | عندكم إيه؟ |
| `order_pizza` | عايز يطلب | عايز بيبروني |
| `track_order` | بيسأل عن طلبه | فين طلبي؟ |
| `affirm` | موافق | تمام / أيوه |
| `deny` | رافض | لا / بدون |
| `cancel` | عايز يلغي | الغي الطلب |
| `thanks` | بيشكر | شكراً |
| `goodbye` | بيمشي | باي |
| `help` | تايه | بتعمل إيه؟ |

وفيه نية حادي عشر مهمة: **`fallback`** — يعني *مفهمتش*. البوت الكويس هو
اللي بيتعامل مع اللي مش فاهمه بأدب، مش اللي بيفهم كل حاجة.

### بنحدد النية إزاي؟

بالكلمات المفتاحية + نظام نقط. كل كلمة بتتطابق بتاخد نقط = **طول الكلمة**.

```python
# الجملة: "فين طلبي"
# track_order: لقى "فين طلبي" (8 حروف) = 8 نقط  ✅ الفايز
# order_pizza: لقى "طلب" (3 حروف)      = 3 نقط
```

**ليه طول الكلمة؟** عشان الجملة الطويلة المحددة تغلب الكلمة القصيرة العامة.
"فين طلبي" أوضح بكتير من مجرد "طلب".

> 🎓 **ده مش Machine Learning.** ده keyword matching. وده مقصود: لما البوت
> يرد غلط، تفتح `nlp.py` وتشوف السبب بعينك في ثانية. لو كان موديل متدرب،
> كنت هتبص على أرقام مش بتقول حاجة. في شغل حقيقي بتبدأ كده، وبعدين تستبدل
> `nlp.py` بموديل متدرب (أو Rasa / Dialogflow) **من غير ما تلمس باقي
> الملفات** — وده بالظبط فايدة إننا فصلناهم.

## 5. المفهوم التاني: الكيانات (Entities)

**النية = عايز إيه. الكيانات = تفاصيل الطلب.**

```
"عايز 2 بيبروني كبيرة بجبنة زيادة"
         │   │        │        │
         │   │        │        └─ extras      = [extra_cheese]
         │   │        └────────── size        = large
         │   └─────────────────── pizza_type  = pepperoni
         └─────────────────────── quantity    = 2
```

النية لوحدها متنفعش. "عايز بيتزا" نية واضحة بس مش كفاية تعمل بيها طلب.
الكيانات هي اللي بتملّي التفاصيل.

### الكيانات اللي بنستخرجها

`pizza_type` · `size` · `quantity` · `extras` · `phone` · `order_id`

### 🐛 أول مشكلة حقيقية واجهتنا

أول ما جربنا، حصل ده:

```
العميل: عايز بيتزا بيبروني      → البوت فهم: بيبروني ✅
العميل: جبنة زيادة وزيتون       → البوت فهم: أربع أجبان ❌❌
```

**ليه؟** كلمة **"جبن"** كانت ضمن كلمات بيتزا الأربع أجبان. و"**جبن**ة زيادة"
جواها "جبن". فالبوت غيّر نوع البيتزا من بيبروني لأربع أجبان — من غير ما
العميل يحس!

ده بالظبط نوع الغلط اللي بيخلي العميل يستلم طلب غلط.

**الحل (مكوّن من جزئين):**
1. شلنا كلمة "جبن" العامة وسبنا "أربع أجبان" المحددة.
2. الأهم: بندوّر على **الإضافات الأول**، وبنشيلها من الجملة، وبعدين ندوّر
   على نوع البيتزا في اللي فاضل.

```python
# بنشيل كل كلمة لقيناها قبل ما ندور على اللي بعدها
"جبنة زيادة وزيتون"  →  نشيل "جبنة زيادة" و"زيتون"  →  يفضل "و"
                        → مفيش نوع بيتزا ✅ صح
```

### 🐛 ونفس المشكلة ظهرت تاني

```
"عايز اربع اجبان كبيرة"  →  quantity = 4  ❌
```

لأن "اربع" رقم! والاسم نفسه فيه رقم. نفس الحل بالظبط: نشيل اسم البيتزا من
الجملة قبل ما ندوّر على الكمية.

> 🎓 **الدرس:** في الـ NLP، الكلمات بتتداخل. القاعدة اللي اتعلمناها اسمها
> **"طابِق واقطع"** (match and cut) — كل ما تلاقي حاجة، شيلها من الجملة
> عشان متتلخبطش مع اللي بعدها. والترتيب مهم: الأكثر تحديداً الأول.

## 6. المفهوم الثالث والأهم: ملء الخانات (Slot Filling)

دي الحاجة اللي بتحوّل "برنامج بيرد" إلى "بوت بيتكلم".

**الخانة (Slot) = معلومة لازمة قبل ما المطبخ يبدأ.**

```python
SLOT_ORDER = ["pizza_type", "size", "quantity", "extras", "address", "phone"]
```

الفكرة في 3 سطور:

1. العميل بيقول أي حاجة → نستخرج منها كل الكيانات.
2. نحطها في الخانات اللي فاضية.
3. ندوّر على **أول خانة لسه فاضية** ونسأل عنها بس.

```python
def _advance(session):
    for slot in SLOT_ORDER:
        if slot not in slots:        # أول خانة فاضية
            return اسأل_عنها(slot)   # اسأل سؤال واحد بس
    return اعرض_الملخص()             # كله اتملى → خلاص
```

### ليه ده عبقري؟

لأنه بيشتغل مهما العميل كتب إزاي:

**عميل بيكتب شوية شوية:**
```
عايز بيتزا          → فاضي: النوع    → "تحب أي نوع؟"
بيبروني             → فاضي: الحجم   → "والحجم؟"
كبيرة               → فاضي: العدد   → "كام واحدة؟"
```

**عميل بيكتب كل حاجة مرة واحدة:**
```
عايز 2 بيبروني كبيرة بجبنة زيادة
→ اتملى: النوع، الحجم، العدد، الإضافات كلهم في خطوة واحدة!
→ فاضي: العنوان → "إيه عنوان التوصيل؟"
```

**نفس الكود بالظبط.** مكتبناش `if` واحدة للحالتين. ده اللي بيخلي البوت
يحس إنه فاهم.

وعشان كده الترتيب متكتبش في سلسلة `if`، كتبناه في **ليستة**. عايز تضيف
سؤال عن نوع العجينة؟ ضيف `"crust"` في الليستة وسؤاله في `QUESTIONS` — خلاص.

## 7. المفهوم الرابع: السياق (Context)

نفس الكلمة معناها بيتغير حسب السؤال اللي قبلها.

```
البوت: تحب تضيف حاجة؟
العميل: لا                  ← يعني "من غير إضافات"

العميل: لا                  ← من غير سياق، دي مش إجابة على حاجة
```

عشان كده فيه دالة `_apply_context()` بتعيد قراءة النية على ضوء السؤال اللي
البوت لسه سائله. أهم 3 حالات:

**1. العنوان** — لما نسأل عن العنوان، **منحللش الجملة خالص**. لو العميل
كتب "14 شارع الجمهورية" وفيها كلمة زي "عايز"، البوت كان هيفتكرها طلب جديد
ويبدأ من الأول. فبناخد النص كله زي ما هو.

**2. 🐛 مشكلة تالتة واجهتنا:** دوست على زرار "**أكد الطلب**" فالبوت عرض
الملخص تاني بدل ما يأكد! ليه؟ لأن "أكد ال**طلب**" جواها كلمة "طلب" =
`order_pizza`، وتعادلت مع "أكد" = `affirm`، والأولوية كانت للطلب.

الحل: في مرحلة التأكيد مفيش غير إجابتين — آه أو لأ. فبنفحص كلمات الموافقة
**مباشرة** من غير ما نستنى نتيجة تصنيف النية.

**3. كلام مش مفهوم في مرحلة التأكيد** — لو العميل كتب حاجة غريبة والطلب
جاهز، البوت بيعرض الملخص تاني ويستنى. **عمره ما بيضيّع طلب كامل** علشان
رسالة واحدة مش مفهومة.

> 🎓 كل المشاكل التلاتة دي اكتشفناها لما شغّلنا البوت وجربناه بجد. **جرّب
> بوتك بنفسك دايماً** — اكتب كلام غريب، اقطع الكلام في النص، اكتب كل حاجة
> مرة واحدة. الـ bugs دي عمرها ما تظهر لو جربت السيناريو المثالي بس.

## 8. الذاكرة — البوت فاكر إزاي؟

HTTP **بينسى**. كل request منفصل تماماً عن اللي قبله. فإزاي البوت فاكر
النوع وهو بيسأل عن الحجم؟

```python
SESSIONS = {}   # في app.py
```

ديكشنري في الرام. كل عميل ليه `session_id` (رقم عشوائي بيتخزن في
`localStorage` في البراوزر). كل request بيبعت الرقم ده، والسيرفر بيجيب
المحادثة بتاعته.

```python
session = SESSIONS.setdefault(session_id, dialog.new_session())
```

شكل الـ session:

```python
{
  "stage":   "filling",                    # في أنهي مرحلة
  "slots":   {"pizza_type": "pepperoni"},  # اتجمع إيه لحد دلوقتي
  "pending": "size"                        # بنستنى إجابة إيه
}
```

> ⚠️ **لو قفلت السيرفر، كل المحادثات المفتوحة بتضيع.** عادي هنا. في مشروع
> حقيقي بتحطها في Redis أو قاعدة بيانات.

**ليه ملف مش قاعدة بيانات حقيقية؟** عشان تشوف الداتا بعينك وانت بتتعلم.

أهم حاجة في تصميم أي نظام.

## 10. الواجهة

`static/index.html` فيه الصفحة كلها: HTML + CSS + JavaScript في ملف واحد.

الجزء المهم في الـ JS كله ده:

```javascript
const res = await fetch('/chat', {
  method: 'POST',
  body: JSON.stringify({session_id: sessionId, message: message})
});
const data = await res.json();
bubble(data.reply, 'bot');      // اعرض الرد
renderChips(data.chips);        // اعرض الأزرار السريعة
```

ابعت نص، استقبل نص، اعرضه. خلاص. **لا منطق ولا أسعار ولا شروط.**

### 🧠 زرار "التحليل"

في الشات فوق على الشمال فيه زرار **🧠 التحليل**. دوس عليه وهتشوف شاشة سودا
بتقولك بعد كل رسالة:

```
intent      : order_pizza
confidence  : 0.75
entities    : {"pizza_type":"pepperoni","size":"large","quantity":2}
slots filled: {"pizza_type":"pepperoni","size":"large","quantity":2}
stage       : filling
asking for  : extras
```

**ده أحسن حاجة في المشروع كله بالنسبة لك.** جرّب تكتب جمل مختلفة وبص على
الشاشة دي — هتشوف دماغ البوت بتفكر إزاي بالظبط. في المشاريع الحقيقية ده
بيتسمى **observability**، وبيبقى مقفول للعملاء ومفتوح للمطورين.

## 11. مسار المحادثة كامل

```
١. ترحيب        →  البوت بيسلّم ويعرض 3 اختيارات
٢. استيعاب      →  "عايز بيبروني" → يستخرج كل الكيانات
٣. ملء الخانات  →  يسأل عن الناقص بس، سؤال واحد كل مرة
٤. تجميع        →  العنوان والموبايل
٥. تأكيد        →  ملخص + السعر النهائي + "أأكد؟"
٦. حفظ          →  رقم طلب PZ-1001 → يتخزن في orders.json
```

وفي أي لحظة العميل يقدر يقول "المنيو إيه؟" — البوت يعرضه **ويرجع يسأل نفس
السؤال اللي كان واقف عنده**. أو يقول "الغي" وكله يترمي.

## 13. عايز تطوره؟ ابدأ من هنا

مرتبين من الأسهل للأصعب:

1. **ضيف نوع بيتزا** — سطر في `PIZZAS` (menu.py) + سطر في `PIZZA_PATTERNS`
   (nlp.py). جرّب ده الأول، هيوصلك الفكرة.
2. **ضيف خانة "نوع العجينة"** — `SLOT_ORDER` + `QUESTIONS` + `QUICK_REPLIES`
   + كيان جديد. ده هيعلمك إزاي المسار كله data مش كود.
3. **خلي العميل يعدّل** — "لا خليها وسط بدل كبير" وهو في مرحلة التأكيد.
4. **اتحقق من رقم الموبايل** — دلوقتي لو العميل كتب رقم غلط، البوت بيعديه؟
   شوف بنفسك واعمل اللي لازم.
5. **استبدل `nlp.py` بموديل حقيقي** — جرب `scikit-learn` أو Claude API.
   **مش هتلمس أي ملف تاني** — وساعتها هتحس بقيمة إننا فصلنا الملفات.

## 14. أهم 5 حاجات تطلع بيها

1. **النية + الكيانات** = فهم الجملة. النية = عايز إيه، الكيانات = التفاصيل.
2. **ملء الخانات** = اللي بيخلي الكلام محادثة. اعرف الناقص، اسأل عنه بس.
3. **السياق بيغلب الكلمات.** نفس الكلمة معناها بيتغير حسب السؤال اللي قبلها.
4. **افصل الطبقات.** الواجهة متعرفش منطق، والمنطق مبيلمسش قاعدة البيانات
   مباشرة. عشان لما تغير حاجة، تغيرها في مكان واحد.
5. **جرّب بنفسك واكسره.** كل bug في الملف ده اتكشف بالتجربة، مش بالقراءة.
